2026-09-17 — SCCR ownership resolved: the cloud is the single writer

  • The SCCR is generated by GitHub Actions (research-data.yml, every 30 min): the public 24h fee endpoint → the live capture → sccr_live.py --frozen → data/sccr*.json. It is Mac-independent by design — the research tier stays fresh when this machine is off.
  • The local com.bsahi.sccr-tracker launchd job (daily, live-DB mode) is Disabled by design, not broken. It would be a second writer of sccr.json and race the cloud. Do not re-enable it without retiring the cloud writer first. Earlier "runs daily locally" references were misleading and are corrected here and in sccr_live_runner.js.
  • Consequence: research-data.yml now stages everything the chain writes — sccr_sensitivity.json, fee_allocation.json, datasets.json, the baked static HTML, and the tokenised research/.html pages — and its rebase-conflict path covers the HTML. Previously it staged sccr.json only, so the cloud wrote those artifacts and then discarded them.
  • Local capture of the other metrics is owned by com.bsahi.collectors (see the same-day persistent-collector entry).

2026-09-17 — Persistent local collectors + a dataset staleness guard

  • New tools/agents/29-local-collectors.js (launchd com.bsahi.collectors, every 15 min) runs each instrument on its own cadence from a ~/.bsahi state file. Legacy /tmp/supervise_*.sh loops retired.

  • Fixed node_census_capture.py: json.load(path) passed a string where a file object is required, crashing on every cached Wayback file.
  • Fixed a two-writer conflict on data/mining_concentration.json: pool_concentration.py (schema v2, MEASURED) is canonical; the legacy mining_concentration.py (v1 stub) now refuses to overwrite a v2 file.

2026-09-17 — node-count semantics correction

  • Incorrect framing removed. The paper described getnodeaddresses returning 32,000 as a lower bound on reachable nodes. It is not: getnodeaddresses 32000 returns addresses from the node's address manager (learned via addr gossip) and 32,000 was the requested ceiling, returned in full. It is a lower bound on gossiped addresses — a set including stale/unreachable entries, sized by peer count and uptime — not a node count and not a bound on reachable nodes. Corrected in model-spec.json, node_census.json, the census agent, and the working paper (§5.4 and all dependent rows).
  • Measured reachable nodes: 26,586 (btcnodes crawl, 2026-09-16) — reported separately from the address sample.
  • Census tool switched to getnodeaddresses 0 (returns all known addresses, per Core docs) so the addrman size is exact rather than truncated at the request ceiling.
  • N = 32,000 marked provisional / deprecated as a node count; the SCCR value is unchanged pending Phase C (re-basing N on the observability model). N 32K -> 26.6K would move the headline ~+20%; the direction is unchanged.
  • New data/verification_population.json and /research/verification-population.
  • Integrity audit added (tools/research/integrity_audit.py): heights/dates monotonicity, anchor consistency, unit agreement, provenance, layer classification. Runs as a gate.
  • Units correction (Observed→corrected): production_cost_ratio.py stored the hash-rate series (unit TH/s) under the field hashrate_ehs — a 10⁶ mislabel. The power calculation was correct; the label was not. Now stores hashrate_ths and a derived hashrate_ehs, and the audit asserts the relation.
